# Changelog

What reached `main` each week: one section per week, headed by its Monday
(dates in UTC), newest first, five lines at most. Every PR adds its line to the
current week's section, creating that section if the week has none. Each line
names the PRs or issues it records. `backend/tests/test_changelog.py` checks
the format.

## Week of 2026-10-26

- Every W and Wh figure in a plan response now carries its own provenance (weakest source, lowest confidence, operational grade, inputs), and the dashboard shows it beside each number, so an estimate can no longer render as a measured watt; a test perturbs each reference field through the calculator to keep the figure-to-input table honest (#79).
- Per-operator API keys: `SUAS_API_KEYS=id:key,...` (the single `SUAS_API_KEY` stays as operator `default`), each mission records the key that planned it (migration 0011 backfills existing ones to `default`), and another key's thread reads, acks and replans exactly as an unknown one (#81). Two follow-up tests kill the mutants CI reported surviving in the new provenance guard and the replan-child owner lookup (#79, #81). A client-chosen `thread_id` must now match `[A-Za-z0-9_-]{1,128}` (422 otherwise), so no one can plan onto another thread's future replan id `<id>:<n>`; lookups still accept stored ids up to 255 characters, and replan and purge skip a child id stored as a thread of its own.
- Each browser is its own operator: the Next server issues an `HttpOnly`, `SameSite=Strict` session cookie and signs it with `SUAS_SESSION_KEY_SECRET` into the key it sends upstream, so two browsers cannot read, ack or replan each other's threads, and cross-origin `POST`s get 403; Compose ships a labelled demo-only secret, and clearing cookies loses that browser's threads (#82). Follow-up tests pin that a key signed with an empty secret is refused when sessions are off, that a secret of exactly 32 characters starts, and that a rate limit of 1 still limits (#82).
- Key rotation keeps open interrupts: rotating a key under the same operator id, or the session secret, keeps a plan that is waiting for a signature, the old key gets 401 once workers restart, and the ack still verifies against `inputs_hash`; tests cover all three key kinds, and ops.md gives the procedure (#83). An opt-in overlap, `SUAS_RETIRED_API_KEYS=id:old-key@expiry`, keeps a rotated direct key working for a short capped window, only from the client IP that last used it (stored by key hash, migration 0013); `X-Forwarded-For` counts only from `SUAS_TRUSTED_PROXIES`, and session keys are unchanged.
- One rate-limit ceiling across workers: `SUAS_RATE_LIMIT_SHARED=true` (Compose's default, since the image runs two workers) keeps each client's sliding window in a locked database row (migration 0012, hashed keys), so N workers no longer allow N times the limit; the in-memory limiter stays the local default, and CI races two workers on Postgres (#84). The always-true `rate_limit_enabled` check is gone: `SUAS_RATE_LIMIT_REQUESTS` must be at least 1, so the limit always applies. Follow-up tests pin the in-memory window's edges (a hit exactly one window old has left it; tracking clears only past the client cap; no hits means no wait) and that each database gets its own `ON CONFLICT` insert (#84). The weather cache is shared the same way: with `SUAS_WEATHER_CACHE_SHARED=true` (Compose's default) each ~1 km cell's last live reading sits in one `weather_cache` row (migration 0014), so worker B serves `cached_fresh` from worker A's fetch; TTL and provenance are unchanged (#85). Retention now repeats every `SUAS_RETENTION_INTERVAL_S` (default 3600s) in every worker instead of only at startup, purges a thread's replan children with it, claims each thread so two workers purge it once, and prunes idle rate-limit rows (#86). A cached weather reading older than `SUAS_WEATHER_STALE_MAX_AGE_S` (default 10800s, at least the TTL) no longer answers an outage as `cached_stale`: the plan gets the same `fallback` or `error` reading an empty cache gives, and the retention pass deletes such shared rows, two workers safely; the in-memory cache drops them on each store. Idle rate-limit pruning now pages through every bucket in key order instead of one unordered batch of 1000, so idle rows behind 1000 live ones are reached, and its delete matches the hits it judged. Migrations are now a deploy step: the image no longer upgrades on every start (so a rollback survives a restart), Compose runs a one-shot `migrate` service before the backend, Railway a `preDeployCommand`, `MIGRATE_ON_START=true` opts a single container back in, and every upgrade holds the Postgres startup lock, so replicas migrating at once serialise instead of colliding on `alembic_version` (#87). Backups are one `pg_dump` of the planner's database (`scripts/backup.sh`, `scripts/restore.sh` into an empty database), and `scripts/verify_restore.py` checks every stored ack's `inputs_hash` against its checkpoint; CI runs the ops.md procedure end to end on Postgres, signing a plan that was pending at backup time (#113). `docs/ops.md` gained four incident playbooks (weather provider down, seal-violation spike, quarantined corpus, leaked key), each naming the metric or log line that signals it, and a test that each named metric is exported with its label and each quoted log line is written by the code (#114). `/metrics` now carries the labels the docs name: plan outcomes by granted `mode`, `suas_weather_source_total{source}` with the reading's real provenance (it had counted cached readings as `fallback`), and `suas_lock_contention_total{lock}` for acks that waited on each other; counters with no emitter were removed from the docs, and a test compares every documented metric and label with the exporter (#112). Every log line now carries `request_id`, `calculator_version`, `weather_source` and `assessment_mode` (`-` until known), including the 500 path, and the access line no longer loses its request id; ops.md shows the one grep (#110). With `SUAS_REQUIRE_POSTGRES` set the app no longer runs `create_all`: a server started before the migrate step on a fresh database exits and names the step, instead of creating tables the migration then failed on. The planning endpoints' request and response shapes are frozen from OpenAPI, so removing a response field or adding a required request field fails CI while an optional addition passes (#115). `scripts/e2e.sh` adds a local browser test against the Compose stack: catalog, plan on fixture weather, acknowledgement and brief through both containers; it stays out of CI so Docker start-up flakes block nothing (#116). A `CALCULATOR_VERSION` bump now fails CI until `eval/fixtures/missions.jsonl` is regenerated with the new version, and the failure names the command to run (#101). LangSmith tracing is opt-in with `SUAS_LANGSMITH_TRACING=true`: runs go through one client that redacts coordinates and every string before sending, LangChain's unredacted `LANGSMITH_TRACING` switch is refused at startup, the client is flushed on shutdown, and the threat model gains the row (#109). Any module in `suas` that imports a network client must now be registered against the threat-model row covering its destination, so a new processor fails CI until its STRIDE row ships with it (#90). The dashboard is rebuilt to an operator-grade standard (docs/ui-standard.md): a fixed three-panel shell (mission form, assessment, review and acknowledge), dense figure tables with each watt's basis in its own column, and every color, size and space from `src/styles/tokens.css`; `npm run lint:ui` in the frontend job fails on template patterns such as gradients, large radii, palette colors and literal colors. An advisory plan now shows a fixed "Advisory, not a clearance" strip with its mode and weather source above the panels, outside every scroll region, and keeps it through a replan; a replan alert on an operational plan raises it too (#91). No brief renders while a plan awaits its signature, the review card shows the full inputs hash it signs, and editing any input after the assessment disables the confirm until it is analyzed again (#92). The weather table shows every source state as its own chip; the dashboard's `WeatherSource` type had only `live` and `fallback`, so a `cached_fresh` reading (operational) read "Fallback defaults", and a test now holds the type to the backend enum (#93). After signing, a live telemetry form replans the mission and shows each briefed figure beside its live value with the change, the alerts by code and message, and an advisory verdict whenever any alert fired (#94). The loading state no longer claims an AI copilot is being prompted, the brief is titled "Safety officer brief" and says when no language model wrote it, failed plan and ack requests say what was not done with the raw reason kept, and a plan with no figures says so (#95). Each W and Wh figure's provenance now lists the record of every input field it rests on (`basis`: value, source, confidence, `source_url`, `retrieved_at`, notes), and the figure's basis label opens a drawer that labels estimates and links cited fields to their documents (#96). The acknowledgement can be completed by keyboard, and focus lands on its outcome rather than the page body; axe-core runs over the planner page in the frontend tests, and the NO-GO colors are held to WCAG AA contrast in both themes (#98). Plan responses now carry `report_source` (`deterministic` or `model`), and the dashboard labels the brief from it; matching the no-key sentence had labelled a failed-call fallback and a brief the seal withheld as model-written. A "Skip to sign-off" link, the first stop after Analyze, takes keyboard users past the figures to the review panel, with axe run while it is focused.
